# Independent MATLAB reference validation

Fixtures in `tests/reference/matlab/warp_factory.npz` were exported by
MATLAB R2025b Update 1 from WarpFactory commit
[`03b10cb02e73998af28db87201a43f2fa0e30319`](https://github.com/NerdsWithAttitudes/WarpFactory/tree/03b10cb02e73998af28db87201a43f2fa0e30319).
They were not generated by Python's implementation. `metadata.json` records
runtime, grid parameters, constants and the raw JSON SHA-256. There are 39
arrays for Minkowski, static Alcubierre and time-dependent Alcubierre.

The 24 direct comparison cases cover metric components, second/fourth Ricci
tensors, second/fourth stress-energy, Eulerian frame transfer, dominant maps
and vorticity. Nonzero compatible core outputs agreed at roughly 1e-15
relative maximum error in the initial export comparison. Tests permit
`rtol=1e-10`, with `atol=max(1e-30, max(abs(reference))*1e-12)` to accommodate
cross-platform roundoff, including near-zero components. Boundaries are
included. These cases validate representative paths, not every possible
metric/parameter combination.

## CPU compatibility required by the installed MATLAB

Parallel Computing Toolbox is absent on the validation machine. Upstream
calls `isgpuarray` on its CPU path, and its vector generator hard-codes a GPU
sphere helper even with `tryGPU=0`. The exporter always prepends two explicit
helpers, whether or not the toolbox is installed, so the export does not
depend on the machine's GPU setup:

- `isgpuarray.m` checks `isa(value, 'gpuArray')`, which is false for these arrays.
- `getEvenPointsOnSphere.m` is the upstream helper with `useGPU=false`, selecting
  the identical CPU formulas instead of attempting a GPU allocation.

The downloaded upstream tree is unchanged. The copied helper retains the
upstream MIT license through the repository LICENSE. No mathematical
formulas are modified for the reference export.

## Intentional differences (not asserted as direct parity)

The fixture also retains null/weak/strong conditions and scalar outputs that
expose known convention differences. They are not silently discarded:

| Output | Upstream behavior | Python behavior |
| --- | --- | --- |
| Null/weak conditions | Lowers Eulerian components using the original curved metric. | Uses the local Minkowski metric for orthonormal-frame components. |
| Weak/strong conditions | Samples speed 1 down to 0, including exactly null vectors. | Samples strictly timelike speeds from 0 up to below 1. |
| Dominant condition | Checks causal flux norm. | Also requires future-directed flux; agrees on the exported cases. |
| Expansion/shear | Uses hard-coded unit spacing in `getScalars`; no ct conversion in `covDiv`. | Uses supplied spacing and converts time derivatives to the ct basis. |
| Comoving Modified Time/Van Den Broeck | g00 uses the original shift term. | Uses the comoving shift, restoring the Alcubierre limiting case. |
| Warp-shell radial sampling | Uses Legendre radial interpolation. | Uses linear interpolation; analytic exterior and zero-mass limits are tested. |

On the exported curved cases, null/weak/strong map differences were roughly
6-14% of the largest map magnitude. Dynamic expansion/shear differ by factors
associated with the 0.5 m grid spacing. Analytic tests in `tests/analyser/`
and `tests/numerical/` check Python's intended behavior independently; passing
parity tests does not claim these corrected outputs are identical upstream.

## Toolbox requirement for the warp-shell reference

Upstream `metricGet_WarpShellComoving` calls `smooth()`, which requires the
MATLAB Curve Fitting Toolbox (or another toolbox that provides it). The
exporter needs it for the two warp-shell cases. It is deliberately **not**
replaced by a stand-in: Python's `_smooth` is itself a reimplementation of
`smooth()`, so a second reimplementation written from the same reading of the
documentation would only confirm the assumption it is meant to test. One shell
case uses `smoothFactor=1`, where `smooth()` reduces to the identity, and the
other uses `smoothFactor=5`, where the window rules (non-integer and even
spans) change the result.

## Known upstream defects

Exporting references for the remaining metric families exposed defects in
upstream `metricGet_ModifiedTime` and `metricGet_ModifiedTimeComoving` at the
pinned commit. They are why Modified Time has no MATLAB reference case.

| Defect | Variant | Effect |
| --- | --- | --- |
| `gridScale` is used but the parameter is named `gridScaling` (line 62) | non-comoving | The function raises "Unrecognized function or variable" on every call that reaches the loop. |
| `x`, `y`, `z` use spacing indices 1, 2, 3 instead of 2, 3, 4 (lines 55-57, 60-62) | both | The x position is scaled by the time spacing, the y position by the x spacing, and so on; results are wrong whenever the spacings differ. |
| The symmetric shift copy reads `tensor{1,2}(t,i,k,k)` instead of `(t,i,j,k)` (line 72) | both | The `{2,1}` component is taken from the wrong cell, so the metric is not symmetric when `j != k`. |

The Alcubierre, Lentz and Van Den Broeck generators use the correct indices
and a symmetric copy, and have reference cases. Python's Modified Time uses
the correct indices; it is checked by its reduction to the Alcubierre metric
(`test_modified_metrics_reduce_to_alcubierre`) and by the generator tests
instead of by MATLAB parity.

## Stability contract for 1.0

The behaviour in the right-hand column above is the supported contract: a
later 1.x release will not change these results. Each difference is pinned
by a test that checks the analytically correct answer, not a recording of
current output.

| Difference | Why Python's behaviour is correct | Pinned by |
| --- | --- | --- |
| Minkowski lowering of Eulerian components | The Eulerian frame is orthonormal, so its metric is already Minkowski; lowering with the curved metric would apply the curvature twice. Dust at rest must report the same density in any coordinates. | `test_conditions_are_frame_independent_in_a_curved_metric` |
| Strictly timelike speeds | A speed of exactly 1 is the null limit, which the Null condition already covers. Speeds are `linspace(0, 1, n, endpoint=False)`. | `test_timelike_speeds_include_rest_and_exclude_the_null_limit`, `test_timelike_samples_are_strictly_timelike` |
| Future-directed dominant flux | The dominant condition requires a future-directed causal flux, so a causal but past-directed flux is a violation. | `test_dust_sign_and_sample_return` (negative density) |
| Expansion and shear scaling | The result for a physical flow must not depend on how finely it is sampled. | `test_expansion_uses_the_supplied_spatial_spacing`, `test_flrw_expansion_shear_and_vorticity` |
| Comoving Modified Time and Van Den Broeck g00 | Both must reduce to Alcubierre when their extra parameters are neutral. | `test_modified_metrics_reduce_to_alcubierre` |
| Linear warp-shell interpolation | The radial profiles are smooth enough that 100,000 linear samples are accurate to about 1e-10 or better; the choice of interpolant is not visible in results. | `test_linear_interpolation_error_is_negligible` |

Because these are conventions of the output, not of the interface, a switch
selecting the upstream behaviour could be added in a 1.x release without
breaking anything. None is provided in 1.0.

## Reproduce

Download and extract the exact commit archive from GitHub into
`.reference-source/`, then run from the repository root:

```powershell
matlab -batch "addpath('tools'); export_matlab_reference('.reference-source/WarpFactory-03b10cb02e73998af28db87201a43f2fa0e30319','tests/reference/matlab/raw.json');"
python tools/convert_matlab_reference.py
python -m pytest tests/reference -q
```

The raw JSON is ignored by Git; compressed arrays and metadata are committed.
The converter only reshapes MATLAB column-major data and compresses it. It
never imports the Python solver. The CI run uses frozen fixtures and needs
no MATLAB license. Review numerical differences before replacing fixtures.
